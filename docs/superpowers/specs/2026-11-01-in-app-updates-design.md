# 软件内更新设计

日期：2026-11-01。范围：Windows x64、现有 Intel iMac macOS 12+ 包。

## 已确认的使用方式
用户最新要求：安装与更新无感。启动后后台检查并自动下载，不弹确认、不要求点更新按钮。准备完成后等待用户正常关闭软件，再自动安装；下次打开即为新版。不强制关闭或重启，不打断使用。检查或下载失败保持安静，继续使用当前版本。

## 方案与取舍
推荐沿用现有免安装压缩包，增加独立更新助手，保留已有 Windows 文件夹和 Mac .app 使用方式。另一种方案是采用 Velopack 等更新框架，但需要迁移现有打包/安装布局。本设计采用前一种；新增助手、校验和失败恢复必须有针对性验证。

## 下载与信任
正式发布继续使用 EAIONE/FontFilter 的 GitHub Releases。国内加速入口可配置，默认使用 HTTPS GitHub 文件代理，失败自动尝试 GitHub 原址。代理只作为传输渠道；发布元数据需使用项目私钥签名，客户端内置公钥，并按受签名保护的 SHA-256 和长度校验下载包。没有可信更新元数据时不把任意旧 ZIP 当成可执行更新。私钥保留在本机开发工具目录，不进入源码包或发布包。

## 安装过程
1. 启动后延迟后台检查并自动下载新版本；同版本、旧版本、预发布、错误平台忽略。
2. 后台下载、校验并解压，完成后等待正常关闭。只在状态栏显示简短状态，不自动关闭主程序。
3. 安全解压到临时目录，拒绝越界路径、符号链接和异常包布局。Mac 包保留执行权限及既有签名，不在用户电脑重新签名。
4. 用户正常关闭时结束扫描并保存人工标签、设置，再启动独立更新助手等待当前进程退出。当前程序不退出时不得强制覆盖。
5. 更新助手校验目标路径，只替换应用文件；本机用户数据目录、字体文件不参与替换。原程序保留为备份，替换或启动失败时恢复旧版并显示可读错误。
6. 成功重启后记录版本；权限不足、只读目录或 Mac 在磁盘映像中运行时给出具体处理提示，不自动提权。

## 版本与发布
GitHub 当前标签是 v1.0，而本地包版本是 0.2.16。新增更新功能的首版统一为 1.1.0，之后使用同一语义版本号。用户首次需要手动安装这个具备更新功能的版本，之后才可在软件内更新。
打包流程同时生成 Win/Mac 包、签名更新元数据及校验文件；新版本只有上传到 Releases 后，客户端才可发现。实现与本地打包不等于发布，未经用户指示不推送或上传。

## 验证与限制
覆盖版本比较、平台选择、代理失败回退、签名/摘要错误、取消、解压越界、退出超时、替换失败恢复及数据保留。Windows 使用隔离的真实字体库副本做界面与助手流程验证。Mac 在当前 Windows 主机可交叉构建、检查包权限和签名摘要；最终安装、重启和 Apple codesign 严格验证需要 Mac 实机。
